Research context · IIT Roorkee

Clinician-facing histopathology annotation platform

A web-based image-labeling platform where clinicians review difficult H&E histopathology images and give expert annotations.

My roleContributor, not sole designer
ContextH&E cardiac histopathology research
Working withClinical collaborators
PeriodAugust 2026 – present
The original platform was a team effort. I contributed to its development and to translating research requirements into the annotation workflow. Sections marked Concept are my own exploratory ideas, not shipped features. I have not run interviews or usability tests, so I report no user outcomes.

Source code and data for this research project are not public.

Overview and problem

The research needed trustworthy ground-truth labels for hard-to-read histopathology images. Only clinicians can supply them, and their time is limited. The problem: how do we make reviewing and labeling an image fast and clear enough that experts will do it carefully?

Target users

Clinicians who review images and give expert labels. Researchers who consume those labels as ground truth for diagnostic research and ML evaluation.

Needs and constraints

Clinicians need a clear view of the image, a low-effort way to label, and confidence that their input was saved. Constraints I worked within: expert time, difficult images that invite uncertainty, and labels that must be consistent enough to evaluate models.

Design decisions I would argue for

Keep the image dominant, limit label choices, always offer an “unsure” path so doubt is recorded instead of forced, and show progress and a clear submit confirmation. These are proposals to validate with clinicians.

Technical implementation

I supported image preparation and quality control for 6,627 H&E images using OpenCV, NumPy, SciPy, MD5 and dHash for duplicate detection, so reviewers don’t spend time on bad or repeated images. I also developed an Attention U-Net for inflammatory region segmentation (83.76% F1, 81.68% precision, 85.95% recall) in the same project. These are model metrics, not usability results.

Learnings and next steps

I learned that the label interface is part of data quality. Next, I would test the proposed flow with clinicians, measure review time and disagreement, and prototype it in Figma.

Self project · research demo

AI-powered medical image classification

A brain-tumor MRI classification interface built with a PyTorch CNN, FastAPI and Streamlit, packaged with Docker Compose.

View code on GitHub

This is a research and demo application. It is not a clinically validated diagnostic system and must not be used for medical decisions.

User problem

A learner or researcher wants to see how a model responds to an MRI image, without running code. The challenge is presenting an AI prediction without overstating certainty.

Flow and states Illustrative mockup

Upload an MRI image
Drop a JPG or PNG here

Research demo only. Not for diagnosis.

Model output

Predicted class: Example class

Model confidence (placeholder value)
Demo result. A model score is not a diagnosis. Consult a qualified clinician.

Interface considerations

Show the demo disclaimer before upload and again beside the result, set expectations on wait time, present confidence as a model score rather than a verdict, and always allow trying another image.

Technical implementation

I trained a PyTorch CNN, exposed it through a FastAPI backend, built the Streamlit interface and containerized everything with Docker Compose.

Limitations and next steps

The model is not clinically validated, and the interface has had no formal usability testing. Next I would add uncertainty communication, accessibility checks and a clearer explanation of what the model does and doesn’t see.

Self-initiated concept

AI Learning Companion for students

A concept for one place where students see their progress, get unstuck, find skill gaps and prepare for placements.

This is my own concept, created for this portfolio. It is not a Newton School product and has not been built, tested or launched. Personas and flows are assumptions.

Problem

Students juggling courses, practice and interview prep often can’t tell what to do next, where they’re weak, or if they’re ready for placements.

Target users

Students preparing for tech roles, including career switchers, who study on their own schedule and need direction more than more content.

Interaction details and rationale

One primary action on Home (“Continue”) reduces choice overload. The assistant sits one tap away on every lesson and quotes the lesson it draws from. Readiness is shown with its inputs so students understand it, instead of a bare score. Skill gaps lead directly to a practice set.
